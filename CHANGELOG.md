# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [семантическое](https://semver.org/lang/ru/).

## [Не выпущено]

### Добавлено
- Крейт `yomi-viewer` — этап M1, локальное чтение:
  - источник страниц: каталог с картинками, CBZ-архив, одиночное
    изображение; служебные файлы (`__MACOSX/`, не-картинки) отсеиваются;
  - естественная сортировка имён: `page2.jpg` идёт перед `page10.jpg`;
  - определение протокола вывода по переменным окружения:
    kitty → iTerm2 → Sixel → юникод-блоки;
  - рендер через графический протокол kitty (с разбиением полезной
    нагрузки на чанки по 4096 байт согласно спецификации);
  - рендер юникод-блоками через символ `▀` и 24-битный цвет — работает
    в любом терминале, две строки пикселей на строку текста;
  - интерактивный цикл: `←`/`→`/`h`/`l`/пробел, `g`/`G`, выход по `q`/`Esc`,
    перерисовка при изменении размера окна.
- Команда `yomi read` подключена к читалке и работает.

### Изменено
- Проект переименован из `manga-cli` в `yomi`: бинарник, крейты
  (`yomi-core`, `yomi-cli`), переменные окружения (`YOMI_*`), пути
  конфигурации и данных (`~/.config/yomi/`).
- Восстановлен полный README: при создании ветки `master` его заглушка
  была ошибочно скопирована поверх рабочей копии и попала в коммит `dev`.

### Исправлено
- Страница больше не растягивается под форму окна. Протокол kitty при
  указании и `c`, и `r` масштабирует изображение на весь прямоугольник,
  не глядя на пропорции; теперь геометрия считается до отправки
  (`yomi-viewer::fit`), и соотношение сторон сохраняется при любом
  размере терминала.
- Страница не увеличивается сверх собственного разрешения (`reader.upscale`,
  по умолчанию `false`) — в полноэкранном терминале лучше поля, чем мыло.
- В kitty уезжает уже уменьшенная страница, а не оригинал в полном
  разрешении: перелистывание перестало гнать мегабайты base64 впустую.
- Рендер блоками использует фильтр Lanczos3 вместо Triangle — заметно
  чище на сильном уменьшении.

### Добавлено (продолжение M1)
- Направление чтения теперь влияет на навигацию: при `right-to-left`
  (умолчание для манги) стрелка влево листает вперёд по сюжету.
  Флаг `--direction rtl|ltr|webtoon` и параметр `reader.direction`.
- Нажатие клавиши и действие со списком страниц разделены: `Input`
  описывает сторону экрана, `Action` — движение по сюжету. Без этого
  разделения направление пришлось бы вплетать в разбор клавиш.
- Строка состояния показывает актуальную подсказку для выбранного
  направления, а не фиксированное «←/→ — листать».

### Известные ограничения
- iTerm2 и Sixel объявлены в цепочке определения, но пока деградируют
  на юникод-блоки.
- Терминалы без графических протоколов (Alacritty, GNOME Terminal)
  показывают приближение блоками — это их ограничение, не ошибка.

## [0.1.0] — этап M0

### Добавлено
- Каркас рабочего пространства Cargo: крейты `yomi-core` и `yomi`.
- Доменная модель: тайтл, глава, страница, поисковый запрос.
- Трейт `Source` и реестр источников с динамической диспетчеризацией.
- Демонстрационный источник `demo` как эталон реализации трейта.
- Конфигурация в TOML с путями по стандарту XDG.
- Разбор командной строки: `read`, `library`, `search`, `download`,
  `sources`, `config`.
- Осмысленные коды возврата для использования в скриптах.
- Логирование через `tracing` в stderr.
- 40 тестов: 29 модульных и 11 интеграционных, запускающих настоящий бинарник, `flake.nix`, CI на GitHub Actions.
