# yomi (読み)

Терминальная читалка манги для Linux. Чтение, поиск и загрузка — без браузера,
без графической оболочки, одним статическим бинарником.

> **Статус: этап M1 (локальное чтение).** Читалка открывает CBZ, каталоги
> и одиночные картинки, определяет протокол вывода терминала и рисует
> через kitty-графику или юникод-блоки. Библиотека и сетевые источники —
> впереди, см. [docs/ROADMAP.md](docs/ROADMAP.md).

## Быстрый старт

```bash
git clone https://github.com/Champloot/yomi.git
cd yomi
cargo build            # отладочная сборка
cargo test             # 77 тестов должны пройти
./target/debug/yomi sources list
```

Релизная сборка (~3,5 МБ, без внешних зависимостей):

```bash
cargo build --release
./target/release/yomi --help
```

## На NixOS

Проект содержит `flake.nix`, поэтому окружение поднимается одной командой:

```bash
nix develop            # среда с rustc, cargo, clippy, rust-analyzer
cargo build
```

Собрать пакет целиком:

```bash
nix build
./result/bin/yomi --version
```

Если пользуетесь `direnv`, в каталоге есть `.envrc` — достаточно `direnv allow`,
и окружение будет подниматься автоматически при входе в каталог.

## Что уже умеет

| Команда | Состояние |
|---|---|
| `yomi sources list` | работает |
| `yomi config init / show / path` | работает |
| `yomi search ЗАПРОС` | работает на демо-источнике |
| `yomi read ПУТЬ` | работает: CBZ, каталог, одиночная картинка |
| `yomi library scan / list` | этап M2 |
| `yomi download ID` | этап M3 |

Нереализованные команды не молчат: они возвращают код 6 и ссылку на этап
дорожной карты. Это осознанное решение — скрипты должны отличать «не умею»
от «сделал».

### Чтение

```bash
yomi read ~/Манга/Тайтл/том-1.cbz
yomi read ~/Манга/Тайтл/том-1/              # каталог с картинками тоже подходит
yomi read страница.png --renderer blocks    # принудительно юникод-блоки
yomi read том-1.cbz --fit width             # по ширине окна (вебтуны)
yomi read том-1.cbz --upscale               # разрешить растягивать сверх оригинала
```

Пропорции страницы сохраняются всегда: расширение окна по горизонтали
не деформирует картинку, а добавляет поля по бокам. По умолчанию страница
не увеличивается сверх своего разрешения — см. `reader.fit` и
`reader.upscale` в [docs/CONFIG.md](docs/CONFIG.md).

Протокол вывода выбирается автоматически (`reader.renderer = "auto"`):
kitty → iTerm2 → Sixel → юникод-блоки, согласно ADR-0003. Сейчас
реализованы два конца цепочки — kitty (полное качество) и блоки
(работают в любом терминале с 24-битным цветом); iTerm2 и Sixel пока
деградируют на блоки.

| Клавиши | Действие |
|---|---|
| `→`, `l`, пробел | следующая страница |
| `←`, `h`, Backspace | предыдущая страница |
| `g` / `G` | первая / последняя страница |
| `q`, `Esc` | выход |

Если картинка выглядит как цветные квадратики — терминал не поддерживает
графических протоколов (так ведут себя Alacritty и GNOME Terminal, это
их принципиальное ограничение, а не ошибка yomi). Проверить, что выбрала
автоматика, можно так:

```bash
yomi -vv read файл.cbz 2>&1 | grep protocol
```

## Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | общая ошибка |
| 2 | неверные аргументы или битый конфиг |
| 4 | не найдено |
| 5 | сеть недоступна |
| 6 | возможность не реализована |
| 70 | внутренняя ошибка |

## Правовая оговорка

`yomi` — клиент, который не размещает и не распространяет контент.
Пользователь сам отвечает за законность доступа к тем источникам,
которые он подключает. Поэтому в основной репозиторий не включаются
источники сомнительного правового статуса — механизм расширений
позволяет подключать их отдельно.
