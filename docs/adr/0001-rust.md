# ADR-0001. Rust как язык реализации

## Контекст

Нужен язык для консольной читалки манги. Ключевые нагрузки: декодирование
JPEG/PNG (десятки мегабайт на главу), масштабирование, кодирование в
графические протоколы терминала, параллельная загрузка десятков файлов.
Пользователь — линуксоид, который ценит скорость и малый размер.

## Решение

Rust.

## Альтернативы

**Go.** Проще язык, быстрее вход, отличная параллельность. Минусы: сборщик
мусора даёт паузы при перерисовке кадров; бинарник в 5–10 раз крупнее;
работа с картинками заметно медленнее.

**Python.** Быстрее всего написать, но время запуска в десятые доли секунды
для CLI неприемлемо, распространение требует интерпретатора и зависимостей,
а обработка изображений упирается в C-библиотеки.

**C/C++.** Скорость та же, но ручное управление памятью и сегфолты при
разборе чужих данных из сети — плохое сочетание.

## Последствия

**Плюсы.** Нет рантайма и GC; бинарник порядка нескольких мегабайт;
`cargo` из коробки даёт сборку, тесты, документацию и зависимости;
экосистема закрывает наши задачи (`image`, `ratatui`, `reqwest`, `rusqlite`).

**Минусы.** Порог входа выше, особенно владение и заимствование.
Компиляция небыстрая. Автору проекта язык незнаком.

**Смягчение.** Написан [docs/rust-primer.md](../rust-primer.md) — разбор
именно того подмножества языка, которое используется здесь. Сложные
конструкции (лайфтаймы, `unsafe`, свои макросы) в проекте не применяются.
