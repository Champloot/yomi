# ADR-0004. SQLite для библиотеки и прогресса чтения

## Контекст

Нужно хранить метаданные тайтлов, список глав, прогресс чтения и историю.
Объём — тысячи записей. Требуется поиск по названию и жанрам.

## Решение

SQLite через `rusqlite`. Файл в каталоге данных XDG. Миграции схемы —
с первого дня, вместе с первой же таблицей. Полнотекстовый поиск — FTS5.

## Альтернативы

**JSON или TOML на диске.** Просто, читается глазами, но перезапись всего
файла при каждом изменении прогресса и линейный поиск по тысячам записей —
тупик. Плюс риск потерять всё при обрыве записи.

**Встроенные key-value хранилища (sled и подобные).** Быстрее на запись,
но нет запросов, всё придётся писать руками.

**Внешняя СУБД.** Абсурд для персональной утилиты.

## Последствия

SQLite даёт транзакции, надёжность при обрыве питания и знакомый язык
запросов. База — обычный файл, его легко скопировать или удалить.

Главное обязательство: **миграции с самого начала**. Без них первое же
изменение схемы заставит пользователей стирать библиотеку — а это
потерянный прогресс чтения, то есть худшее, что мы можем сделать.
