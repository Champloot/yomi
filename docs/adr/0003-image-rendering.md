# ADR-0003. Цепочка деградации при выводе картинок

## Контекст

Единого способа показать изображение в терминале не существует. kitty,
WezTerm, foot, xterm, Alacritty и GNOME Terminal поддерживают разные
протоколы либо не поддерживают ничего. Пользователь при этом ожидает,
что программа просто заработает.

## Решение

Определять возможности терминала во время выполнения и выбирать лучший
доступный способ:

```
kitty graphics → iTerm2 → Sixel → юникод-блоки
```

Юникод-блоки — гарантированный запасной путь: работают везде, качество
низкое. Пользователь может навязать конкретный способ параметром
`reader.renderer` или флагом `--renderer` — прежде всего для отладки.

## Альтернативы

**Только kitty-протокол.** Лучшее качество, но отсекает большинство
терминалов.

**Только внешняя утилита `chafa`.** Просто, но добавляет обязательную
зависимость и не даёт настоящей графики там, где она есть.

**Своя библиотека абстракции с первого дня.** Преждевременно: пока не
написан хотя бы один вывод, неясно, какой должна быть абстракция.

## Последствия

Определение возможностей — отдельная нетривиальная задача: переменные
окружения ненадёжны, нужен запрос DA1 с разбором ответа и таймаутом.
tmux требует passthrough и, вероятно, будет отдельной веткой кода.
Тестировать придётся вручную на нескольких терминалах — автоматизировать
это практически невозможно.
