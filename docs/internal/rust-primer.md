# Rust для тех, кто писал на Go и Python

Этот документ объясняет **только тот Rust, который есть в этом проекте**.
Не учебник: цель — чтобы вы открыли любой файл и понимали каждую строчку.
Читать подряд, с открытым кодом рядом.

Полноценный учебник, когда захочется вглубь: [«Язык программирования
Rust»](https://doc.rust-lang.ru/book/) — официальная книга, переведена.

---

## 0. Три идеи, из которых следует всё остальное

**Идея первая: нет сборщика мусора и нет ручного `free`.** У каждого значения
есть ровно один владелец. Владелец вышел из области видимости — память
освобождена. Компилятор проверяет это на этапе сборки, поэтому программа
не платит за GC-паузы во время выполнения. Именно поэтому мы выбрали Rust:
перерисовка кадра в терминале не должна замирать на уборке мусора.

**Идея вторая: ошибки — это обычные значения.** Нет исключений, как в Python.
Нет `if err != nil` на каждой строке, как в Go, — есть оператор `?`, который
делает то же самое одним символом.

**Идея третья: если компилируется — скорее всего работает.** Компилятор
придирчив до раздражения. Это плата вперёд: то, что в Python выстрелит
у пользователя через месяц, здесь не соберётся сегодня.

## 1. Как устроен проект: крейты и модули

**Крейт** (crate) — единица компиляции, аналог Go-модуля или Python-пакета.
Крейты бывают двух видов: библиотека (`lib.rs`) и программа (`main.rs`).

У нас их два, и это принципиально:

```
crates/yomi-core/   → библиотека: вся логика
crates/yomi-cli/    → программа: разбор аргументов и печать
```

Такое разделение называется **workspace** (рабочее пространство) — описано
в корневом `Cargo.toml`. Зачем: ядро можно будет использовать из TUI, из
тестов и из будущего демона, не таща за собой `clap` и печать в терминал.

**Модуль** (module) — файл или каталог внутри крейта, аналог Python-модуля.
Объявляется явно, автоматического подхвата файлов нет:

```rust
// crates/yomi-core/src/lib.rs
pub mod config;   // ← подключает файл src/config.rs
pub mod sources;  // ← подключает src/sources.rs, а тот — src/sources/demo.rs
```

Забыли строчку `pub mod` — файл просто не попадёт в сборку. Это регулярная
ошибка новичка: «я создал файл, а он не видится».

`pub` — публичность. Без него элемент виден только внутри своего модуля.
В Go это было заглавной буквой имени; здесь — явным ключевым словом.

**`use`** — сокращение записи, аналог `from x import y`:

```rust
use yomi_core::model::SearchQuery;  // теперь можно писать просто SearchQuery
```

Обратите внимание: в коде `yomi_core` с подчёркиванием, а в `Cargo.toml`
пакет называется `yomi-core` с дефисом. Так и надо: дефис в имени пакета,
подчёркивание в имени в коде.

## 2. Переменные, строки, ссылки

```rust
let x = 5;          // неизменяемая по умолчанию
let mut y = 5;      // изменяемая, mut = mutable
y += 1;             // так можно только с mut
```

Неизменяемость по умолчанию — не придирка, а способ понять, кто что портит.

**Два строковых типа**, и это первое, обо что спотыкаются:

| Тип | Что это | Аналогия |
|---|---|---|
| `String` | владеющая строка, живёт в куче, можно менять | `str` в Python, `string` в Go, который вы сконструировали |
| `&str` | «взгляд» на чужую строку, ничем не владеет | срез/slice чужой памяти |

Правило на каждый день: **аргументы функций принимают `&str`, поля структур
хранят `String`**. Именно так в нашем коде:

```rust
pub fn get(&self, id: &str) -> Result<Arc<dyn Source>>   // принимаем взгляд
pub struct Manga { pub title: String, ... }              // храним владение
```

Превращения: `"текст".to_string()` или `"текст".into()` даёт `String`;
`&моя_строка` даёт `&str`.

**Символ `&` означает «ссылка», то есть заимствование без передачи владения.**

```rust
fn печатает(m: &Manga) { ... }   // одолжили почитать, вернём
fn съедает(m: Manga)  { ... }    // отдали навсегда, у вызывающего больше нет
```

Правило заимствования: одновременно можно иметь либо сколько угодно
`&` (читателей), либо ровно один `&mut` (писателя). Никогда одновременно.
Это то самое, что защищает от гонок данных, и то самое, из-за чего
компилятор иногда ругается там, где в Go всё «работало».

Если компилятор упёрся и непонятно, что он хочет, — не воюйте, поставьте
`.clone()`. Да, это лишнее копирование. На картинках манги это неважно,
а разобраться можно позже. `clone()` — легальный инструмент, не позор.

## 3. Структуры, перечисления, `derive`

Структура — это `struct` из Go, dataclass из Python:

```rust
pub struct Chapter {
    pub number: Option<f32>,
    pub language: String,
}
```

**Перечисление (`enum`) в Rust мощнее, чем в Go и Python.** Это не список
констант, а «одно из», причём каждый вариант может нести данные:

```rust
pub enum PageLocation {
    Url(String),                                     // вариант со строкой
    File(PathBuf),                                   // вариант с путём
    Archive { archive: PathBuf, entry: String },     // вариант с полями
}
```

Разбирается через `match` — и компилятор заставит перечислить **все**
варианты. Забыли один — не соберётся. Это огромная страховка при
рефакторинге: добавили формат — компилятор сам покажет все места, где
его надо обработать.

```rust
match kind {
    InputKind::Unsupported => bail!("неподдерживаемый формат"),
    InputKind::Cbr => bail!("CBR пока не поддерживается"),
    _ => Err(not_implemented("чтение страниц", "M1")),  // _ = «все остальные»
}
```

**`#[derive(...)]` — автогенерация кода.** Строчка

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, Default)]
pub struct Config { ... }
```

просит компилятор написать за вас: отладочную печать (`Debug`),
копирование (`Clone`), сравнение (`PartialEq`), сериализацию в TOML/JSON
(`Serialize`/`Deserialize`), значения по умолчанию (`Default`).
Это метапрограммирование на этапе компиляции, без цены во время работы.

Строчки вида `#[serde(default)]` — настройки этой автогенерации. Например
`#[serde(deny_unknown_fields)]` в нашем конфиге означает: опечатка в
`config.toml` станет ошибкой, а не будет молча проигнорирована.

## 4. `Option` и `Result` — вместо `None`, `nil` и исключений

**`Option<T>`** — значение либо есть, либо нет. Заменяет `None` из Python и
`nil` из Go. Разница принципиальная: **`Option` нельзя случайно
разыменовать**, компилятор потребует обработать оба случая. Отсюда
отсутствие в Rust класса ошибок NullPointerException как явления.

```rust
pub year: Option<u16>,          // год может быть неизвестен
manga.year.unwrap_or(0)         // взять или подставить 0
if let Some(y) = manga.year { ... }   // сделать что-то, только если есть
```

**`Result<T, E>`** — успех или ошибка. Полный аналог пары `(value, err)`
из Go, но забыть проверить нельзя.

```rust
pub fn config_dir() -> Result<PathBuf>
```

**Оператор `?`** — главное удобство языка. Он означает: «если ошибка —
немедленно вернуть её из текущей функции, иначе развернуть значение».

```rust
let raw = std::fs::read_to_string(&path)?;   // одна строка
```

То же самое на Go заняло бы четыре строки с `if err != nil`. Ставьте `?`
почти везде — это норма, а не хак.

Два типа ошибок в проекте, и это осознанное разделение:

| Где | Чем | Почему |
|---|---|---|
| `yomi-core` | `thiserror`, перечисление `Error` | библиотека обязана давать вызывающему разбираемые варианты ошибок |
| `yomi` | `anyhow::Result` | программе всё равно, что произошло, ей надо напечатать и выйти |

`anyhow` умеет добавлять пояснения по цепочке:

```rust
.with_context(|| format!("источник «{}»", args.source))?
```

Пользователь увидит и контекст, и первопричину: `Ошибка: источник
«mangadex»: источник «mangadex» не найден`.

## 5. Трейты — сердце нашей архитектуры

**Трейт (`trait`) — это интерфейс из Go**, набор методов, которые тип
обязуется реализовать. В отличие от Go, реализация объявляется явно.

Весь замысел расширяемости проекта держится на одном трейте:

```rust
#[async_trait]
pub trait Source: Send + Sync {
    fn id(&self) -> SourceId;
    async fn search(&self, query: &SearchQuery) -> Result<SearchResult>;
    async fn chapters(&self, manga_id: &str) -> Result<Vec<Chapter>>;
}
```

Любой источник — MangaDex, локальная папка, что угодно — реализует его,
и ядро больше ничего о нём знать не обязано:

```rust
#[async_trait]
impl Source for DemoSource {
    fn id(&self) -> SourceId { SourceId::new(ID) }
    async fn search(&self, query: &SearchQuery) -> Result<SearchResult> { ... }
}
```

Расшифровка загадочных мест в этом объявлении:

- **`Send + Sync`** — обещание, что тип безопасно передавать между потоками.
  Нужно, потому что при пакетной загрузке источник будут дёргать
  несколько задач одновременно.
- **`#[async_trait]`** — костыль (в хорошем смысле). Rust умеет `async fn`
  в трейтах, но тогда трейт нельзя положить в `Box`/`Arc` и хранить
  списком. Нам это необходимо, поэтому используем крейт `async-trait`.
- **`dyn Source`** — «какой-то тип, реализующий Source, какой именно —
  выяснится во время выполнения». Динамическая диспетчеризация,
  как интерфейс в Go.
- **`Arc<dyn Source>`** — `Arc` это счётчик ссылок (аналог `shared_ptr`).
  Нужен, чтобы один источник могли одновременно держать и загрузчик,
  и интерфейс. `Rc` — то же самое, но без потокобезопасности; нам не годится.

`&self` в методе — это Python-овский `self`, только явной ссылкой.

## 6. Асинхронность

`async fn` — функция, которая может «приостановиться» на ожидании сети
и отдать процессор другой задаче. Ключевое отличие от Go: **горутин нет,
рантайм не встроен в язык**, его подключают крейтом. У нас `tokio`.

```rust
let result = source.search(&query).await?;
//                                 ^^^^^ без .await ничего не выполнится
```

Забыть `.await` — типичная ошибка. Компилятор предупредит: вы получите
«future, который никто не опросил».

Запуск рантайма у нас руками, в `main.rs`, а не через `#[tokio::main]` —
чтобы было видно, что это осознанный шаг, и чтобы потом ограничить число
потоков на слабых машинах.

На этапе M0 сеть ещё не нужна, но интерфейс `Source` объявлен асинхронным
сразу: переписывать его позже было бы больно.

## 7. Тесты

Тесты живут **в том же файле**, что и код, — это нормально и принято:

```rust
#[cfg(test)]              // компилировать только при `cargo test`
mod tests {
    use super::*;         // втянуть всё из родительского модуля

    #[test]
    fn defaults_are_russian_first() {
        let c = Config::default();
        assert_eq!(c.general.language, "ru");
    }

    #[tokio::test]        // для асинхронных тестов
    async fn search_works() { ... }
}
```

Интеграционные тесты — отдельно, в каталоге `tests/`: они видят крейт
снаружи, как настоящий пользователь. Наш `crates/yomi-cli/tests/cli.rs`
запускает собранный бинарник и проверяет вывод и коды возврата.

Запуск: `cargo test --workspace`. Всё, никаких конфигов.

## 8. Что делать, когда компилятор ругается

Ошибки Rust многословны, но полезны — в отличие от почти любого другого
языка, их стоит читать целиком. В конце обычно лежит готовое решение.

Подробное объяснение по коду ошибки:

```bash
rustc --explain E0502
```

Три самые частые ситуации у новичка:

**«cannot borrow as mutable more than once» / «borrowed value does not live
long enough».** Вы уперлись в проверку заимствований. Быстрое лечение —
`.clone()`. Правильное — понять, кто владеет данными; это приходит с опытом,
не тормозите на этом сейчас.

**«expected `String`, found `&str`»** (или наоборот). Добавьте `.to_string()`
либо `&`. См. раздел 2.

**«no method named X found»**. Часто не хватает `use` нужного трейта:
методы трейта видны, только если трейт втянут в область видимости.

Отдельно: `cargo clippy` — линтер, который знает сотни идиом и подсказывает,
как написать лучше. Запускайте регулярно, он учит языку эффективнее статей.

## 9. Ежедневный набор команд

```bash
cargo check          # быстро проверить, что компилируется (без сборки)
cargo test           # тесты
cargo run -- search Пример   # запустить; всё после -- уходит программе
cargo build --release        # оптимизированная сборка
cargo fmt --all      # форматирование, единый стиль без споров
cargo clippy         # линтер
cargo add ИМЯ        # добавить зависимость
cargo doc --open     # документация по всем зависимостям, локально
```

`cargo check` в несколько раз быстрее сборки — им и пользуйтесь в цикле
«написал — проверил».

## 10. Чего в этом проекте намеренно нет

Чтобы вы не искали в коде то, чего там не должно быть:

- **`unsafe`** — не используется и не должен появиться без записи в ADR.
- **Макросы своего сочинения** — только чужие (`derive`, `format!`, `vec!`).
- **Сложные времена жизни (`'a`)** — почти отсутствуют. Если начали писать
  структуру с лайфтаймом, скорее всего проще положить `String` вместо `&str`.
- **Наследование** — его в Rust нет вовсе. Композиция и трейты.
