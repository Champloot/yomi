# Дорожная карта

Принцип прежний: каждый этап — вертикальный срез, который можно
запустить и которым можно пользоваться.

Фокус — локальная работа с файлами: прочитать, собрать, разметить.
Ничего из этого не зависит от чужих серверов.

## M5 — форматы ◐ PDF и CBR готовы, сжатие впереди

- [x] **PDF** через извлечение встроенных изображений (`lopdf`, без
      рендера страницы). Поддержаны `DCTDecode` (JPEG — подавляющее
      большинство сканов) и несжатые/`FlateDecode` `DeviceGray`/`DeviceRGB`
      8 бит на канал
- [x] Честный отказ на всём файле, если хоть одна страница не подходит
      (векторная вёрстка, `JPXDecode`, `CCITTFaxDecode`, экзотичная
      глубина цвета) — с указанием номера страницы и причины
- [x] CBR/RAR через внешний `unar`. Понятная ошибка при отсутствии
      утилиты, со ссылкой на ADR-0006 и подсказкой, что установить
- [ ] `library optimize` — перекодирование в AVIF/WebP, 30–50% экономии.
      Отложено: `ravif`/`rav1e` — тяжёлые кодеки с долгой сборкой, и в
      этой среде разработки нет возможности сравнить визуальное качество
      до/после на реальных сканах. Возвращаться стоит с готовностью
      подождать долгую сборку и с реальными файлами для сравнения

## Заморожено

**Загрузка из сети** — реализована и работает в ветке `net`, из
основной сборки исключена. Причина продуктовая: MangaDex ведёт себя
корректно, но лицензированные тайтлы отдаёт ссылкой на сторонний сайт,
а лицензируют как раз популярное.

Вернуть имеет смысл вместе с источником, который поддерживается честно
и целиком: **Komga или Kavita** — самостоятельно поднимаемые
медиасерверы с документированным API. Правовых вопросов нет, а
аудитория совпадает: кто держит Komga, тот живёт в терминале.

**Плагинная система** — отложена вместе с сетью. Архитектура готова
(трейт `Source`, реестр, `Capabilities`), протокол продуман: внешний
процесс с обменом JSON через stdin/stdout. Возвращаться стоит, когда
появится второй непохожий источник.

**Полнотекстовый поиск через FTS5** — `LIKE` по сотням тайтлов
мгновенный, виртуальная таблица с триггерами окупится на тысячах.

**Сверка разбиения с числом страниц глав из API** — годится как
проверка гипотезы, но не как способ вычислить границы: чужой скан
содержит обложки и послесловия, и накопительная сумма съезжает.

## Чего не будет

| Что | Почему |
|---|---|
| Обход анти-бот защиты | без headless-браузера не решается |
| Одинаковая картинка во всех терминалах | Alacritty и GNOME Terminal не поддерживают графику |
| Доступ к лицензионному контенту | не техническая задача |
| Механическое разбиение тома по числу страниц | ошибается почти всегда, но выглядит уверенно |
| Перевод и OCR | по объёму отдельный проект |

### Что выяснено про API MangaDex

Проверено по официальной документации, август 2026:

- `GET /at-home/server/:chapterId` отдаёт `chapter.data` — упорядоченный
  массив имён файлов страниц. Его длина и есть точное число страниц.
  У объекта главы есть и поле `pages`, но массив достовернее: это
  буквально то, что будет скачано.
- Базовый URL для картинок живёт около 15 минут, затем нужен повторный
  запрос. Хардкодить его нельзя — адрес подбирается по геолокации.
- На запросы картинок нельзя слать заголовки авторизации: при обращении
  к стороннему узлу сети это утечка токена.
- Обязательна отправка отчётов об успехе и сбое загрузки на
  `api.mangadex.network/report`. Это условие пользования сетью, а не
  пожелание: по этим отчётам отслеживается здоровье узлов.
- Условия использования: без рекламы и продажи доступа, с указанием
  команд перевода и исполнением их запросов на удаление.

**Про сверку разбиения.** API знает страницы своих глав — уже
разделённых. Локальный том — чужой скан со своей нумерацией: обложка,
оглавление, реклама, послесловие. Считать границы накопительной суммой
нельзя, погрешность копится. А вот как проверку гипотезы использовать
стоит: если разбиение по разворотам дало главы на 22/25/26 страниц, а
API говорит 21/24/26 — совпадение по форме подтверждает, что границы
найдены верно.

Заметки сохранены на случай возвращения к ветке `net`.

## Первые шаги: три упражнения

Чтобы освоиться в коде, не ломая архитектуру. По возрастанию сложности.
Делать до начала M1.

**Упражнение 1. Новое поле в модели.**
Добавьте `Manga.rating: Option<f32>` и выведите его в `yomi search`.
Затронете: `model.rs`, `sources/demo.rs`, `commands/search.rs`.
Цель — почувствовать, как компилятор ведёт вас по всем местам, где
нужна правка. Проверка: `cargo test` зелёный.

**Упражнение 2. Новая команда.**
Сделайте `yomi info <ID> --source demo`, печатающую подробности тайтла
и список его глав. Понадобится: новый вариант в `cli.rs`, новый файл
в `commands/`, строчка в `commands/mod.rs`. Всё нужное в ядре уже есть —
методы `Source::manga` и `Source::chapters`. Добавьте тест в `tests/cli.rs`.

**Упражнение 3. Новый источник.**
Реализуйте источник `local`, считающий мангой каждый подкаталог указанной
папки. Это уже полезная работа — по сути начало M2.
Инструкция: [sources.md](sources.md).

После третьего упражнения приступайте к M1.

Заметки сохранены на случай возвращения к ветке `net`.
