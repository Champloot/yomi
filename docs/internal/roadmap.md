Принцип: каждый этап — **вертикальный срез**, который можно запустить
и которым можно пользоваться. Не «сначала все модули на 30%».

Про FTS5. Поиск по библиотеке работает обычным `LIKE`, и на нескольких
сотнях тайтлов он мгновенный. FTS5 потребовал бы виртуальной таблицы и
триггеров синхронизации с основной, а ощутимый выигрыш появляется на
тысячах записей и при поиске по описаниям. Вернёмся к этому, когда
появится, что искать: после M3 в библиотеке окажутся сетевые тайтлы
с полными метаданными.

## Ручная разметка глав (после M3)

Идея пользователя, и она бьёт автоматику по надёжности: разметка,
сделанная человеком один раз, достовернее любой эвристики.

Замысел: во время чтения нажатием клавиши (скажем, `m`) отметить
текущую страницу как начало главы. Отметки складываются в базу и
привязываются к файлу, а не к сеансу. Дальше том ведёт себя как
набор глав: навигация по главам, отдельный прогресс, осмысленные
названия в списке.

Что нужно продумать при реализации:

- **Хранение.** Новая таблица `chapter_marks` (chapter_id, page,
  title). Схема поднимется до версии 3. Отметки не должны теряться
  при пересканировании — то же правило, что и для прогресса.
- **Правка.** Ошибиться легко, поэтому нужны и снятие отметки, и
  переименование. Минимум: `m` — поставить или снять, ввод названия
  необязателен (по умолчанию «Глава N» по порядку).
- **Ввод текста в сыром режиме.** Читалка работает в raw mode и
  перехватывает клавиши посимвольно. Ввод названия потребует
  отдельного мини-режима со строкой ввода внизу экрана.
- **Экспорт в ComicInfo.xml.** Разметку стоит уметь записывать
  обратно в архив закладками `Bookmark` — тогда ей смогут
  воспользоваться Komga, Kavita и Mihon, а не только yomi. Это
  превращает ручную работу пользователя в переносимый результат.
- **Подсказка от автоматики.** Логично при входе в режим разметки
  предзаполнить границы тем, что нашла эвристика по разворотам:
  человеку останется поправить, а не размечать с нуля.

**Не проверено на живом API.** В среде разработки нет доступа к
api.mangadex.org, поэтому проверены разбор ответов на записанных
образцах, сборка URL, лимиты и повторы. Первый запуск против настоящего
сервиса — за пользователем.

### Что выяснено про API MangaDex

Проверено по официальной документации, август 2026:

- `GET /at-home/server/:chapterId` отдаёт `chapter.data` — упорядоченный
  массив имён файлов страниц. Его длина и есть точное число страниц.
  У объекта главы есть и поле `pages`, но массив достовернее: это
  буквально то, что будет скачано.
- Базовый URL для картинок живёт около 15 минут, затем нужен повторный
  запрос. Хардкодить его нельзя — адрес подбирается по геолокации.
- На запросы картинок нельзя слать заголовки авторизации: при обращении
  к стороннему узлу сети это утечка токена.
- Обязательна отправка отчётов об успехе и сбое загрузки на
  `api.mangadex.network/report`. Это условие пользования сетью, а не
  пожелание: по этим отчётам отслеживается здоровье узлов.
- Условия использования: без рекламы и продажи доступа, с указанием
  команд перевода и исполнением их запросов на удаление.

**Про сверку разбиения.** API знает страницы своих глав — уже
разделённых. Локальный том — чужой скан со своей нумерацией: обложка,
оглавление, реклама, послесловие. Считать границы накопительной суммой
нельзя, погрешность копится. А вот как проверку гипотезы использовать
стоит: если разбиение по разворотам дало главы на 22/25/26 страниц, а
API говорит 21/24/26 — совпадение по форме подтверждает, что границы
найдены верно.

## Отложено сознательно

| Что | Почему |
|---|---|
| CBR/RAR | лицензия `unrar` несвободна; нужен `libarchive` извне |
| PDF | тяжёлая зависимость ради редкого формата |
| Синхронизация с Mihon | разбор формата `.tachibk` — отдельная работа |
| Трекеры (Shikimori, AniList) | нужен OAuth и хранение токенов |
| Перевод и OCR | по объёму — отдельный проект |

## Чего не будет

- **Гарантированной работы источников за Cloudflare.** Без headless-браузера
  это не решается. Честная пометка `fragile` вместо обещаний.
- **Одинаковой картинки во всех терминалах.** В Alacritty и GNOME Terminal
  графических протоколов нет — только юникод-приближение.
- **Доступа к лицензионному контенту.** Это не техническая задача.

## Первые шаги: три упражнения

Чтобы освоиться в коде, не ломая архитектуру. По возрастанию сложности.
Делать до начала M1.

**Упражнение 1. Новое поле в модели.**
Добавьте `Manga.rating: Option<f32>` и выведите его в `yomi search`.
Затронете: `model.rs`, `sources/demo.rs`, `commands/search.rs`.
Цель — почувствовать, как компилятор ведёт вас по всем местам, где
нужна правка. Проверка: `cargo test` зелёный.

**Упражнение 2. Новая команда.**
Сделайте `yomi info <ID> --source demo`, печатающую подробности тайтла
и список его глав. Понадобится: новый вариант в `cli.rs`, новый файл
в `commands/`, строчка в `commands/mod.rs`. Всё нужное в ядре уже есть —
методы `Source::manga` и `Source::chapters`. Добавьте тест в `tests/cli.rs`.

**Упражнение 3. Новый источник.**
Реализуйте источник `local`, считающий мангой каждый подкаталог указанной
папки. Это уже полезная работа — по сути начало M2.
Инструкция: [sources.md](../sources.md).

После третьего упражнения приступайте к M1.
