# Дорожная карта

Принцип прежний: каждый этап — **вертикальный срез**, который можно
запустить и которым можно пользоваться. Не «сначала все модули на 30%».

Фокус проекта — локальное чтение. Загрузка из сети реализована, но
отключена и живёт в ветке `net`; почему — в разделе «Заморожено».

> Нумерация изменилась после отказа от сети. Прежние M4 (TUI) и M6
> (выпуск) стали M8 и M7 соответственно; ADR со ссылками на старые
> номера не переписывались — история решений ценнее аккуратности.

## M4 — ручная разметка глав

Самое ценное из оставшегося: превращает любой том без разметки в
удобно читаемый набор глав. Идея пользователя, и по надёжности она
бьёт любую автоматику — человек размечает один раз и точно.

- [ ] Отметка текущей страницы как начала главы прямо в читалке (`m`)
- [ ] Хранение отметок в отдельной таблице (схема до версии 3);
      пересканирование их не теряет — то же правило, что для прогресса
- [ ] Снятие и переименование отметки: ошибиться легко
- [ ] Ввод названия в сыром режиме терминала — отдельный мини-режим
      со строкой внизу экрана, примерно половина работы этапа
- [ ] Предзаполнение границами, найденными эвристикой по разворотам:
      править проще, чем размечать 200 страниц с нуля
- [ ] Экспорт разметки в `ComicInfo.xml` закладками `Bookmark`

Последний пункт — ключевой по ценности. Он делает ручной труд
переносимым: размеченный том откроется по главам в Komga, Kavita и
Mihon, а не только в yomi.

- [ ] Навигация по главам внутри тома: переход к следующей/предыдущей
- [ ] Отдельный прогресс чтения по главам, а не по тому целиком

## M5 — форматы

Расширяет то, что вообще можно открыть.

- [ ] **PDF** через извлечение встроенных изображений чистым
      Rust-парсером (`lopdf` или аналог). Манга-сканы почти всегда —
      это одна растровая картинка на страницу, и вытащить её на порядок
      проще полноценного рендера. Полный рендер потребовал бы pdfium
      или poppler, а это убивает идею единого статического бинарника
- [ ] Честный отказ на PDF с векторной вёрсткой — редкий случай,
      но сообщение должно объяснять причину
- [ ] Оптимизация размера библиотеки: перекодирование страниц в AVIF
      или WebP, экономия 30–50% на реальных сканах. Только явной
      командой `yomi library optimize`, никогда автоматически:
      потеря качества редких сканов необратима
- [ ] CBR/RAR через внешний `unar`, если он есть в системе — с внятным
      сообщением, когда его нет (лицензия `unrar` несвободна, см. ADR-0006)

## M9 — синхронизация с Шикимори

Трекер прогресса, а не источник контента: через него ничего не
скачивается, поэтому отказ от сетевых источников этому не мешает.

- [ ] OAuth2 в терминале: показать ссылку, пользователь авторизуется
      в браузере и возвращает код — так делает `gh auth login`,
      браузерный редирект без GUI не работает
- [ ] Хранение токена: не в конфиге рядом с настройками, а отдельно,
      с правами 600
- [ ] Ручная привязка `yomi track link <id> <shikimori-id>`.
      Автоматическое сопоставление по названию надёжно не решается —
      тот же путь выбрал Mihon
- [ ] Отправка прогресса при закрытии главы
- [ ] Соблюдение лимитов частоты запросов — та же дисциплина,
      что была в сетевом источнике
- [ ] Разрешение конфликтов: прочитано и локально, и на сайте

## Заморожено

**Загрузка из сети** — реализована, работает, вынесена в ветку `net`.
Причина продуктовая, а не правовая: MangaDex ведёт себя корректно, но
лицензированные тайтлы отдаёт ссылкой на сторонний сайт, а лицензируют
как раз популярное. Функция, заявленная в справке и не работающая на
тех тайтлах, ради которых её ищут, раздражает сильнее, чем её
отсутствие.

Вернуть имеет смысл вместе с источником, который поддерживается
честно и целиком: **Komga или Kavita** — самостоятельно поднимаемые
медиасерверы с документированным API. Пользователь держит коллекцию на
своём сервере и читает её откуда угодно; правовых вопросов нет, а
аудитория совпадает — кто держит Komga, тот живёт в терминале.

**Плагинная система для сторонних источников** — отложена вместе с
сетью. Архитектура под неё готова (трейт `Source`, реестр,
`Capabilities`), протокол продуман: внешний процесс с обменом JSON
через stdin/stdout. Возвращаться к ней стоит, когда появится второй
непохожий источник, — на одном MangaDex интерфейс не проверить, он под
него и написан.

**Полнотекстовый поиск через FTS5** — `LIKE` по сотням тайтлов
мгновенный, а виртуальная таблица с триггерами синхронизации окупится
только на тысячах записей с описаниями.

### Что выяснено про API MangaDex

Проверено по официальной документации, август 2026:

- `GET /at-home/server/:chapterId` отдаёт `chapter.data` — упорядоченный
  массив имён файлов страниц. Его длина и есть точное число страниц.
  У объекта главы есть и поле `pages`, но массив достовернее: это
  буквально то, что будет скачано.
- Базовый URL для картинок живёт около 15 минут, затем нужен повторный
  запрос. Хардкодить его нельзя — адрес подбирается по геолокации.
- На запросы картинок нельзя слать заголовки авторизации: при обращении
  к стороннему узлу сети это утечка токена.
- Обязательна отправка отчётов об успехе и сбое загрузки на
  `api.mangadex.network/report`. Это условие пользования сетью, а не
  пожелание: по этим отчётам отслеживается здоровье узлов.
- Условия использования: без рекламы и продажи доступа, с указанием
  команд перевода и исполнением их запросов на удаление.

**Про сверку разбиения.** API знает страницы своих глав — уже
разделённых. Локальный том — чужой скан со своей нумерацией: обложка,
оглавление, реклама, послесловие. Считать границы накопительной суммой
нельзя, погрешность копится. А вот как проверку гипотезы использовать
стоит: если разбиение по разворотам дало главы на 22/25/26 страниц, а
API говорит 21/24/26 — совпадение по форме подтверждает, что границы
найдены верно.

Заметки сохранены на случай возвращения к ветке `net`.

## Первые шаги: три упражнения

Чтобы освоиться в коде, не ломая архитектуру. По возрастанию сложности.
Делать до начала M1.

**Упражнение 1. Новое поле в модели.**
Добавьте `Manga.rating: Option<f32>` и выведите его в `yomi search`.
Затронете: `model.rs`, `sources/demo.rs`, `commands/search.rs`.
Цель — почувствовать, как компилятор ведёт вас по всем местам, где
нужна правка. Проверка: `cargo test` зелёный.

**Упражнение 2. Новая команда.**
Сделайте `yomi info <ID> --source demo`, печатающую подробности тайтла
и список его глав. Понадобится: новый вариант в `cli.rs`, новый файл
в `commands/`, строчка в `commands/mod.rs`. Всё нужное в ядре уже есть —
методы `Source::manga` и `Source::chapters`. Добавьте тест в `tests/cli.rs`.

**Упражнение 3. Новый источник.**
Реализуйте источник `local`, считающий мангой каждый подкаталог указанной
папки. Это уже полезная работа — по сути начало M2.
Инструкция: [sources.md](../sources.md).

После третьего упражнения приступайте к M1.
