# Как добавить источник манги

Источник — единственная точка расширения, которая не требует правок в ядре.
Эталонный пример: `crates/yomi-core/src/sources/demo.rs`.

## Пять шагов

**1. Создайте файл** `crates/yomi-core/src/sources/имя.rs`.

**2. Зарегистрируйте модуль** в `crates/yomi-core/src/sources.rs`:

```rust
pub mod demo;
pub mod имя;   // ← добавить
```

Без этой строчки файл не попадёт в сборку. Это самая частая ошибка.

**3. Опишите тип и реализуйте трейт:**

```rust
use crate::model::{Chapter, Manga, Page, SearchQuery, SearchResult, SourceId};
use crate::source::{Capabilities, Source};
use crate::{Error, Result};
use async_trait::async_trait;

pub const ID: &str = "имя";

pub struct МойИсточник { /* HTTP-клиент, кэш и прочее */ }

#[async_trait]
impl Source for МойИсточник {
    fn id(&self) -> SourceId { SourceId::new(ID) }
    fn name(&self) -> &str { "Читаемое название" }

    fn capabilities(&self) -> Capabilities {
        Capabilities {
            text_search: true,
            filter_by_genre: true,
            filter_by_author: false,   // ← честно: сайт этого не умеет
            fragile: true,             // ← честно: стоит анти-бот защита
            ..Default::default()
        }
    }

    async fn search(&self, query: &SearchQuery) -> Result<SearchResult> { todo!() }
    async fn manga(&self, id: &str) -> Result<Manga> { todo!() }
    async fn chapters(&self, manga_id: &str) -> Result<Vec<Chapter>> { todo!() }
    async fn pages(&self, chapter_id: &str) -> Result<Vec<Page>> { todo!() }
}
```

**4. Добавьте в реестр** — `crates/yomi-core/src/source.rs`, функция
`default_registry()`.

**5. Напишите тесты** в том же файле, в блоке `#[cfg(test)] mod tests`.

Проверка: `yomi sources list` показывает новый источник,
`yomi search запрос -s имя` возвращает результаты.

## Обязательные требования

**Честно заполняйте `Capabilities`.** Если объявить `filter_by_author: true`
там, где сайт этого не умеет, интерфейс начнёт врать пользователю: он
предложит фильтр, который молча ничего не сделает. Флаг `fragile: true`
обязателен для всего, что стоит за анти-бот защитой.

**Соблюдайте лимиты сайта.** Ограничение частоты запросов — на стороне
источника, не пользователя. Превышение лимитов приведёт к блокировке по IP,
и пострадает не разработчик, а тот, кто поставил утилиту. У MangaDex лимиты
описаны в документации API, у остальных — выясняются опытом; берите
заведомо щадящие значения.

**Не глотайте ошибки.** Возвращайте `Error::NotFound` для отсутствующего
тайтла, `Error::Unsupported` для неподдерживаемой возможности. Пустой
результат вместо ошибки — плохо: пользователь не поймёт, сломалось у него
или искомого правда нет.

**Не тащите зависимости в ядро без нужды.** Если источнику нужна экзотика,
это повод обсудить отдельный крейт.

## Тестирование без сети

Тесты **не имеют права ходить в сеть**: они должны проходить в CI, в поезде
и на машине без интернета. Способы:

- сохраните реальный ответ сайта в `tests/fixtures/` и разбирайте его;
- вынесите HTTP-клиент за трейт и подставляйте заглушку в тестах;
- на крайний случай пометьте `#[ignore]` и запускайте вручную через
  `cargo test -- --ignored`.

Разбор ответа (парсинг) тестировать обязательно: именно он ломается,
когда сайт меняет вёрстку.

## Юридическая сторона

В основной репозиторий входят источники с официальным публичным API
и понятными правилами использования. Всё остальное — плагины, которые
пользователь подключает сам и под свою ответственность.

Проект — клиент, аналогичный браузеру: он не хранит и не раздаёт контент.
Это не индульгенция, но и не повод делать вид, что вопрос не существует:
не встраивайте в основной репозиторий обход платных подписок и защит.
